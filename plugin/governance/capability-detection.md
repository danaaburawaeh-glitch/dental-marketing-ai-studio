# اكتشاف القدرة والتراجع اليدوي — Capability Detection & Graceful Degradation v1.0.0

هذا المستند يُوثِّق ويُعمِّم نمطاً كان موجوداً جزئياً في الاستوديو منذ v1.1 (قسم «مصادر البيانات — بهذا الترتيب» في مهارات `instagram/*`) إلى مبدأ حوكمة صريح يُطبَّق على **كل** تكامل اختياري في الحزمة، لا التحليلات فقط. لا يستبدل النمط القائم — يُثبّته كقاعدة ملزمة لأي Skill جديدة.

## المبدأ

> لا تفترض وجود أي MCP أو API أو Connector أو Skill أو external assistant. تحقق أولاً، ثم استخدم إن وُجد، وإلا تراجع إلى وضع يدوي كامل بلا فشل.

```
detect_capabilities()
  إن وُجدت الأداة (المكوّن مربوط وفعّال) → استخدمها لتنفيذ الجزء الآلي من المهمة
  إن لم تُوجد أو تعذّر الوصول إليها     → Manual Execution Mode (انظر أدناه) — لا توقف، لا فشل
```

هذا ليس دالة برمجية حرفية تُستدعى — هو **مفهوم إلزامي** يُطبَّق نثراً في كل Skill تذكر تكاملاً اختيارياً في `tool_dependencies`: تحقق فعلي من توفر الأداة قبل افتراض استخدامها، وليس افتراضاً مسبقاً.

## التكاملات الاختيارية في هذه الحزمة

| التكامل | يُستخدم في | ماذا يوفّر عند توفره |
|---|---|---|
| ChatPlace (انستغرام، وواتساب عند ربطه) | مهارات `instagram/*`، `content-whatsapp-lead-responder` | قراءة محادثات/تعليقات فعلية، إرسال رد مباشر |
| Meta Ads | مهارات تحليل الأداء، `marketing-strategy-planner` | مؤشرات إعلانية ومحتوى فعلي |
| Windsor.ai | نفس ما سبق | مؤشرات عضوية عبر منصات متعددة |
| Canva | `content-case-post-reviewer`، `content-social-calendar-scheduler`، `content-short-form-video-planner` | توليد تصميم فعلي |
| Google Drive / Calendar / Gmail | مهارات النظام، `content-social-calendar-scheduler` | تخزين، جدولة فعلية، مسودات بريد |
| WebSearch / WebFetch | مهارات تتطلب تحقق معلومة | تحقق حي من ادعاء أو معلومة سوق |

لا واحدة من هذه إلزامية. **لا Skill في هذه الحزمة تتوقف كلياً عن العمل بسبب غياب أي منها.**

## نمط Progressive Enhancement — كيف يُكتب في SKILL.md

كل Skill تذكر تكاملاً اختيارياً في `tool_dependencies` تلتزم بهذا الشكل في جسمها (أو ما يعادله وظيفياً):

```
إن توفر [الأداة]:
  نفّذ الجزء الآلي (قراءة/إرسال/توليد) عبرها مباشرة.

وإلا (Manual Execution Mode):
  لا تتوقف. قدّم بدلاً منه:
  - تحليل أو توصية مبنية على ما هو متوفر من سياق
  - مخرَج نصي جاهز للنسخ يدوياً
  - قائمة تحقق أو خطوة تالية واضحة
  - إشارة صريحة أن التنفيذ الفعلي يدوي الآن
```

مثال حرفي مطبَّق فعلياً (من `skills/content-whatsapp-lead-responder/SKILL.md`):

> إن توفر ChatPlace: اقرأ سجل المحادثة الفعلي... وقدّم خيار إرسال الرد مباشرة.
> إن لم يتوفر: لا تتوقف ولا تفشل. اعمل بالسياق النصي المقدَّم، وسلّم النص كاملاً جاهزاً للنسخ اليدوي، مع خطوة تالية واضحة.

## Manual Execution Mode — الحد الأدنى المطلوب

عند غياب أي تكامل اختياري، المخرَج البديل يجب أن يحمل **الأربعة** التالية كحد أدنى (مطابقة لبند ١٤ من طلب الترقية):

1. **تحليل** — ما الذي يقوله السياق المتوفر، بلا انتظار بيانات آلية
2. **توصية** — الإجراء المقترَح بناءً على هذا التحليل
3. **مخرَج جاهز للنسخ** — نص أو جدول قابل للاستخدام فوراً يدوياً
4. **الخطوة التالية** — إجراء واحد واضح يعرف المستخدم ما يفعله بعد استلام المخرَج

## من يتحقق من الالتزام بهذا النمط

`system-assistant-builder` (عند بناء Skill جديدة) يرفض حفظ أي Skill تذكر `tool_dependencies` غير فارغة دون توثيق مسار Manual Execution Mode المقابل في جسم الملف. `tests/standalone/` يختبر هذا فعلياً لسيناريوهين محددين (غياب WhatsApp، غياب أي تكامل تسويقي/اجتماعي).

## العلاقة بالوثائق الأخرى

```

tests/standalone/                  ← الاختبار التنفيذي لسيناريوهات الغياب
```
