# دورة الحياة والإصدارات — Lifecycle & Semantic Versioning v1.0.0

## دورة الحياة

القيم المسموحة **حصراً**:

| الحالة | المعنى | يدخل الـ routing التلقائي؟ |
|---|---|---|
| `DRAFT` | قيد البناء، غير صالح للاستخدام | ✘ |
| `TESTING` | مكتمل بنيوياً، تحت الاختبار، غير معتمد | ✘ |
| `PILOT` | تجربة محدودة | ✘ — **بالاستدعاء الصريح بالاسم فقط** |
| `ACTIVE` | معتمد | ✔ |
| `DEPRECATED` | له بديل، يبقى مؤقتاً لعدم كسر الطلبات القديمة | ✘ — يُحال إلى `deprecated_by` |
| `ARCHIVED` | غير صالح للاستدعاء إطلاقاً | ✘ |

**قاعدة الـ routing:** `ACTIVE` فقط يدخل التوجيه التلقائي. `PILOT` يعمل عند طلب المستخدمة له بالاسم أو داخل بيئة اختبار. `DEPRECATED` لا ينفّذ — يعلن بديله ويحوّل. `ARCHIVED` لا يُستدعى بأي حال.

### الانتقالات المسموحة

```
DRAFT → TESTING → PILOT → ACTIVE
                    ↘_______↗
ACTIVE → DEPRECATED → ARCHIVED
ACTIVE → TESTING           (عند فشل اختبار أو تعديل جوهري)
أي حالة → ARCHIVED         (بقرار موثَّق)
```

الانتقال إلى `ACTIVE` **لا يجوز** إلا بعد:

1. اجتياز `validate_system.py` بلا أخطاء
2. اجتياز اختبارات الـ routing الخاصة به
3. `last_tested_version == version`

## الإصدارات — Semantic Versioning

```
MAJOR.MINOR.PATCH
```

| المستوى | متى | مثال |
|---|---|---|
| **PATCH** | تصحيح إملائي · توضيح صياغة · تصحيح metadata · إصلاح لا يغيّر السلوك المتوقع | `1.0.0 → 1.0.1` |
| **MINOR** | عبارة تشغيل جديدة · قدرة مخرَج جديدة · اعتماد معرفة جديد · مهارة مضافة | `1.0.0 → 1.1.0` |
| **MAJOR** | تغيّر الغرض · تغيّر الحدود · تغيّر مسار العمل · كسر اعتمادية · تغيّر منطق القرار | `1.0.0 → 2.0.0` |

**تغيير `assistant_id` هو MAJOR دائماً** ويستوجب قيداً في خريطة الترحيل و `legacy_aliases`.

## قفل الاختبار — `last_tested_version`

القاعدة الحاكمة:

```
status == ACTIVE  ⟹  last_tested_version == version
```

إن اختلفا، الحالة الصحيحة هي `TESTING` لا `ACTIVE`. الفاحص يفرض ذلك ويفشل البناء عند خرقه.

بعبارة أخرى: **رفع الإصدار يُسقط الاعتماد تلقائياً** حتى يُعاد الاختبار. لا يوجد مساعد «معتمد» بنسخة لم تُجرَّب.

### ما يُعد اختباراً

| المستوى | المطلوب |
|---|---|
| بنيوي | `validate_system.py` بلا أخطاء |
| توجيه | كل `triggers` تصيب هذا المساعد، وكل `negative_triggers` تصيب `route_to` |
| تشغيلي | تشغيلة حقيقية واحدة على مثال من عمل الطبيب/ة، ومراجعة المخرَج |
| حدود | حالة يجب أن يرفضها المساعد — ويرفضها فعلاً |

`HIGH` و `CRITICAL` يلزمها المستويات الأربعة. `LOW` و `MODERATE` يكفيها الأول والثاني، مع تسجيل ذلك في `notes`.

## سجل التغيير

كل تغيير جوهري يُسجَّل في `governance/foundation-validation-report.md` أو في سجل التغيير الخاص بالمرحلة، بالحقول: المعرّف · من إصدار ← إلى إصدار · المستوى · السبب · التاريخ.

## الأرشفة لا الحذف

`ARCHIVED` هي البديل عن الحذف. الملف يبقى، ويُنقل إلى قسم «مؤرشف» في الدليل، ويُمنع استدعاؤه. الحذف الفعلي قرار بشري منفصل يُتخذ بعد فترة ثبات، ولا تنفّذه الأدوات.
